# Hardware Design

## 1. 目的

Home Digital Signageに必要なハードウェア構成を決定する。

## 3. 要件整理

### 3.1 なぜ整理するのか

洗い出した項目には、

- 実現したい機能
- 性能・品質
- ハードウェア
- 将来構想
- 技術的な実現手段
- 学習目標

が混在していた。

そのため、製品選定の前に目的と手段を分離する。

### 3.2 分類

- 機能要件
- 非機能要件
- ハードウェア要件
- 拡張要件
- 制約条件
- 学習目標
- 開発方針

## 4. 優先順位の整理

### 考え方

すべてを初期バージョンで実現する必要はない。

そのため、

- MVP = サイネージとして成立する最小構成
- v1.0 = 自宅に壁掛けして日常利用できる完成版
- Future = v1.0完成後の拡張
- Out of Scope = 今回は実装しない

に分類する。

### 整理結果

| 機能要件                 | フェーズ        | 理由                                                    |
| -------------------- | ----------- | ----------------------------------------------------- |
| 時計を常時表示する            | **MVP**     | 掛け時計としての基本機能であり、サイネージの核となるため                          |
| 予定を表示する              | **MVP**     | 単なる時計ではなく家庭用情報ボードとしての価値を持たせるため                        |
| 現在の気温を表示する           | **MVP**     | 単なる時計ではなく、日常的に利用できる情報を表示するため                          |
| 天気予報を表示する            | **MVP**     | 日常的な情報表示に加え、外部データを取得して表示する基本構成を検証するため                 |
| 写真を表示する              | **Future**  | 情報サイネージとして成立するためには必須ではなく、完成後に追加可能なため                  |

## Raspberry Pi本体の選定

### 選定条件

Raspberry Pi本体は、以下の観点から選定する。

- Web UIを日常利用に支障なく動作させられる処理性能
- OS・ブラウザ・アプリを同時実行できるメモリ容量
- Full HD程度の映像出力
- Wi-Fi接続
- Bluetooth接続
- GPIOによるセンサー拡張
- カメラ接続
- USB等による周辺機器拡張
- 音声出力手段
- 長時間稼働可能な冷却構成
- 壁掛け筐体へ組み込めるサイズ・重量
- 消費電力・電源要件
- プロジェクト全体の予算を圧迫しない価格

### 特に比較する項目

- CPU性能
- RAM容量
- 映像出力
- GPIO・カメラ等の拡張性
- 発熱・必要な冷却
- 消費電力
- 本体価格

## 7. 採用判断

### 採用

#### Raspberry Pi 5 2GB

### 理由

1. **デジタルサイネージとして十分な処理性能がある**

   Raspberry Pi 5はRaspberry Pi 4と比較してCPU性能が向上しており、
   Chromiumの起動やWebページの表示など、Webブラウザを利用した処理でも
   高い性能を確認できた。

   本プロジェクトではWeb UIを利用してサイネージ画面を表示する予定であるため、
   Pi 5の処理性能は画面表示や将来の機能追加に対する余裕につながると判断した。

2. **将来的な機能拡張に対応しやすい**

   GPIO、USB、カメラインターフェースなど、
   センサー・カメラ等を追加するために必要なインターフェースを備えている。

   また、PCIeを利用したNVMe SSDなどのストレージ拡張も可能であり、
   現時点では利用予定はないものの、将来的な拡張の選択肢を確保できる。

3. **長時間稼働を考慮した冷却構成を取りやすい**

   本プロジェクトでは長時間連続稼働を想定しているため、
   ヒートシンクとファンによる冷却を行う方針としている。

   Raspberry Pi 5には専用のファンコネクタが搭載されており、
   GPIOを冷却ファンへの給電に使用せずに冷却機構を構成できる。

   将来的にGPIOへセンサー等を接続することを考えると、
   GPIOを他の用途に確保できる点もメリットと判断した。

4. **消費電力の増加を許容できると判断した**

   Raspberry Pi 5はPi 4と比較して高負荷時の消費電力が大きい傾向がある。

   一方、確認した実測結果ではアイドル時の消費電力差は小さく、
   本プロジェクトではCPUを常時高負荷で動作させる予定はない。

   そのため、Pi 5の性能向上と将来の拡張余地を考慮すると、
   消費電力の増加は許容できる範囲と判断した。

5. **2GBを現時点で必要十分なRAM容量と判断した**

   MVPでは主に、

   - Raspberry Pi OS
   - Webブラウザ
   - サイネージWeb UI
   - API取得等のバックグラウンド処理
   - ログ・キャッシュ

   を動作させる予定である。

   現時点では4GBを必要とする明確な処理は予定しておらず、
   2GBでMVPを実現できる可能性が高いと判断した。

   また、調査時点ではDigiKeyにおける2GBモデルと4GBモデルの価格差が
   約8,200円あり、将来的に必要になる可能性だけを理由として
   4GBを選択する費用対効果は低いと判断した。

   ただし、実際のメモリ使用量は実装後に確認し、
   `free -h` や `htop` 等を使用してRAM使用量およびSwap使用量を測定する。

6. **価格と性能のバランスが良い**

   Pi 4とPi 5の同容量モデルを比較した場合、
   本体価格の差に対してPi 5ではCPU性能やWebブラウザ性能、
   ストレージ性能、拡張性などの向上が得られる。

   また、2GBモデルを選択することで、
   Pi 5の性能・拡張性を確保しながら本体価格を抑えることができる。

   以上から、今回の要件では
   **Raspberry Pi 5 2GBが性能・拡張性・価格のバランスに優れている**
   と判断し、採用する。

### 懸念事項

- 調査時点ではDigiKeyのRaspberry Pi 5 2GBが在庫切れのため、
  購入時に在庫・納期・価格を再確認する。

- 2GB RAMでMVPを長時間安定稼働できるかは実機で未検証のため、
  MVP実装後にRAM使用量・Swap使用量を測定する。

- 本体価格だけでなく、
  電源・冷却部品・ストレージ等を含めた総額が
  プロジェクトのハードウェア予算内に収まることを確認する。


### 不採用候補

#### Raspberry Pi Zero 2 W

不採用理由：

1. GPIOを利用するにはヘッダーピンのはんだ付けが必要であり、
   現在ははんだ付けに必要な工具・設備を所有していない。

2. CPUが1GHz Cortex-A53、メモリが512MBであり、
   基本的なデジタルサイネージ用途では利用可能と考えられるが、
   OS・Webブラウザ・Web UI・API通信等を同時に動作させる今回の構成では
   性能面の余裕が小さい。

3. 本プロジェクトでは将来的にセンサー、カメラ、クラウド連携などの
   機能拡張を予定しているため、拡張後の処理負荷を考慮すると
   より性能に余裕のあるモデルが適していると判断した。

小型・低価格・低消費電力という利点はあるものの、
今回は本体サイズや価格を最優先するのではなく、
開発のしやすさと将来の拡張余地を重視して候補から除外する。

### 画面サイズ

10～12インチ程度を候補とし、11インチ前後を第一候補とする。

設置予定の部屋は約11畳で、最大2～3m程度離れた位置から
画面を確認することを想定している。

手元の11インチiPadを使用して実際の視認性を確認したところ、
画面上部2/3程度を使用してデジタル時計を表示すれば、
想定する距離からでも十分に時刻を確認できた。

そのため、視認性については画面サイズを大きくするだけではなく、
文字サイズやレイアウトなどのUI設計によって調整可能と判断した。

以上から、壁掛け時計程度のサイズ感や壁掛け時の重量・取り回しも考慮し、
11インチ前後を第一候補とする。

### 解像度

Full HD（1920×1080）以上を選定条件とする。

解像度は高いほど文字や画像を滑らかに表示できるため、
可能であれば高解像度のディスプレイを採用したい。

一方、本プロジェクトでは11インチ前後のディスプレイを
最大2～3m程度離れた位置から見ることを想定しているため、
必要以上に高い解像度による効果は限定的になる可能性がある。

そのため、Full HDを最低条件とし、
WQHD等のより高解像度な製品については、
価格差やその他のスペックを比較した上で採用を判断する。


### 輝度

室内で日常利用するために十分な輝度を確保できること。

一般的な屋内用ディスプレイの輝度を参考にしつつ、
設置予定の部屋では日中・照明点灯時・夜間などで
周囲の明るさが大きく変化するため、
特定の輝度だけでなく調整可能な範囲も重視する。

現時点では実際にどの程度の輝度が適切か判断しにくいため、
可能な限り輝度調整幅の広い製品を優先する。
ただし、価格とのバランスを考慮して最終判断する。

また、将来的には環境光センサー等を利用して、
周囲の明るさに応じた輝度の自動調整も検討する。

そのため、ディスプレイ選定時には以下を確認する。

- 最大・最小輝度
- 輝度調整が可能か
- Raspberry Pi / OS側からソフトウェアで輝度を制御可能か
- 輝度調整幅
- 価格

具体的な適正輝度については、
実機導入後に日中・夜間等の環境で確認して調整する。

### 視野角

壁掛けしたディスプレイを部屋の複数の位置から確認するため、
広い視野角を持つディスプレイを優先する。

特に、ディスプレイを目線より少し高い位置へ設置する予定のため、
水平方向だけでなく、下方向から見た場合の視認性も重視する。

製品選定ではIPS系のパネルを優先し、
水平・垂直ともに178°程度の広視野角を目安とする。

ただし、178°を必須条件とはせず、
価格やその他のスペックとのバランスを考慮して判断する。

最終的な視認性については、
実際の設置位置から画面を確認して評価する。

壁掛け方針\
賃貸住宅で使用するため、壁への加工を可能な限り少なくする。ディスプレイ単体を壁へ固定するのではなく、Raspberry Pi・冷却機構・ディスプレイを一体化した軽量な筐体を作成し、完成品全体を壁掛けする構成を基本方針とする。そのため、ディスプレイ選定ではVESA対応よりも、重量・厚さ・Piとの一体化のしやすさを重視する。

⑤は「一体型端末を作る」という完成イメージに一番近い。\
⑦は「自作筐体へ組み込む」場合の対抗候補。\
⑧のVESAという強みは今回あまり重要ではなくなる

### ディスプレイ

#### 採用
Raspberry Pi Touch Display 2 10インチ

#### 採用理由

1. 画面サイズ
   - 10インチで、第一候補としていた11インチ前後の条件を満たす。
   - 手持ちの11インチiPadを使用した実験で、2～3m程度離れた位置からでも
     UI設計によって時計を十分確認できることを確認した。

2. 解像度
   - 1200 × 1920 Pixels。
   - サイネージ用途として必要としていたFHD相当以上の表示領域を確保できる。

3. Raspberry Pi 5との互換性
   - Raspberry Pi公式製品であり、Raspberry Pi 5に正式対応している。
   - Pi 5をディスプレイ背面へ取り付けられるため、一体型端末を構成しやすい。

4. 配線
   - DSIで映像とタッチを接続できる。
   - ディスプレイへの電源もPi側から供給できるため、
     一体化した場合の内部配線を比較的シンプルにできる。
   - 外部への電源配線を1系統にまとめられる構成を目指せる。

5. 輝度制御
   - Raspberry Pi OS側から輝度を制御できる。
   - 将来的に環境光センサーを追加した場合、
     周囲の明るさに応じた自動輝度調整へ発展させやすい。

6. 重量・厚み
   - ディスプレイ単体は約482g。
   - Pi 5 + Active Coolerを含めても約560g前後と見積もられ、
     軽量な一体型端末を構成できる見込み。
   - 筐体を含めて600～700g程度、厚さ30～40mm程度を
     初期設計目標とする。

7. 壁掛けとの相性
   - 賃貸住宅で使用するため、壁への加工を可能な限り少なくしたい。
   - VESAマウントによる固定よりも、
     Display + Pi 5 + Active Coolerを一体化して軽量化する方針と相性が良い。

8. 価格
   - 約17,000～18,000円程度。
   - 他の有力候補と大きな価格差がなく、
     プロジェクト全体予算5～6万円の範囲内で採用可能と判断した。

#### 比較候補
Waveshare 10.1EP-CAPLCD

1920×1200、IPS、広視野角、300cd/m²、スピーカー搭載など
ディスプレイ単体の性能では優れている点があった。

一方、本プロジェクトでは表示性能だけでなく、
Raspberry Pi 5との一体化、配線の簡素化、ソフトウェアからの
輝度制御、軽量・薄型化を重視した。

そのため、Raspberry Pi公式製品としてPi 5との統合性が高い
Touch Display 2を採用した。

Apple HomeはHomeKit/Matter対応アクセサリをまとめて管理し、照明・センサー・ロック・サーモスタットなどの状態確認や操作、さらに時刻・位置情報・センサー・他アクセサリの状態をトリガーにしたオートメーションを扱える。

                Apple Home
                    │
       ┌────────────┼────────────┐
       │            │            │
     温度計        照明       人感センサー
       │            │            │
       └────────────┼────────────┘
                    │
             Raspberry Pi
                    │
             Digital Signage

             
| アイデア      | できること                     |
| --------- | ------------------------- |
| 室温・湿度表示   | Homeに登録したセンサー情報を表示        |
| 人感連動      | 人がいるときだけ画面ON              |
| 帰宅モード     | 帰宅したら時計＋今日の予定＋天気を表示       |
| 外出モード     | 全員外出したら画面OFF              |
| おやすみモード   | 夜は時計だけ＋最低輝度               |
| 照明状態表示    | 「リビング照明 ON」などを表示          |
| スマートホーム操作 | 将来的に画面から照明等を操作            |
| Siri連携    | Siriを含むApple Home側から家電を操作 |

Raspberry Piを「Homeのアクセサリ」にする方向もある\
Apple Homeは現在、HomeKitだけでなくMatter対応アクセサリも扱える

Raspberry PiをApple Homeへ直接どう組み込むかは別途技術選定が必要です。HomeKit/Matterのどちらを使うか、ブリッジを挟むかなど複数の実装方法がある。
