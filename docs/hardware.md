# Hardware Design

## 1. 目的

Home Digital Signageに必要なハードウェア構成を決定する。

---

## 3. 要件整理

### 3.1 なぜ整理するのか

洗い出した項目には、

- 実現したい機能
- 性能・品質
- ハードウェア
- 将来構想
- 技術的な実現手段
- 学習目標

が混在していた。

そのため、製品選定の前に目的と手段を分離する。

### 3.2 分類

- 機能要件
- 非機能要件
- ハードウェア要件
- 拡張要件
- 制約条件
- 学習目標
- 開発方針

## 4. 優先順位の整理

### 考え方

すべてを初期バージョンで実現する必要はない。

そのため、

- MVP = サイネージとして成立する最小構成
- v1.0 = 自宅に壁掛けして日常利用できる完成版
- Future = v1.0完成後の拡張
- Out of Scope = 今回は実装しない

に分類する。

### 整理結果

| 機能要件                 | フェーズ        | 理由                                                    |
| -------------------- | ----------- | ----------------------------------------------------- |
| 時計を常時表示する            | **MVP**     | 掛け時計としての基本機能であり、サイネージの核となるため                          |
| 予定を表示する              | **MVP**     | 単なる時計ではなく家庭用情報ボードとしての価値を持たせるため                        |
| 現在の気温を表示する           | **MVP**     | 単なる時計ではなく、日常的に利用できる情報を表示するため                          |
| 天気予報を表示する            | **MVP**     | 日常的な情報表示に加え、外部データを取得して表示する基本構成を検証するため                 |
| 写真を表示する              | **Future**  | 情報サイネージとして成立するためには必須ではなく、完成後に追加可能なため                  |
| 複数写真をスライドショー表示する     | **Future**  | 写真表示機能の拡張として、写真表示と合わせて将来実装するため                        |
| 時計以外のコンテンツを自動切り替えする  | **MVP**     | ユーザーが操作せずに複数の情報を確認できるサイネージの基本動作を実現するため                |
| 時間帯に応じてコンテンツを切り替える   | **v1.0**    | MVP成立には不要だが、日常利用時の利便性を高められるため                         |
| 表示コンテンツのON/OFFを変更できる | **Future**  | MVPではコンテンツ数が少なく、コンテンツのカスタマイズが必要になってから実装すればよいため        |
| コンテンツの表示順を変更できる      | **Future**  | コンテンツのカスタマイズ機能を追加する段階で必要になるため                         |
| コンテンツごとの表示時間を変更できる   | **Future**  | コンテンツのカスタマイズ機能を追加する段階で必要になるため                         |
| スマートフォンから操作できる       | **Future**  | サイネージ本体の完成後、操作性・利便性を向上させるための機能だから                     |
| PCから操作できる            | **Future※** | PC専用機能としては設けず、将来Web管理画面を実装する場合にスマートフォン等と合わせて対応を検討するため |
| 音声を再生できる             | **Future**  | MVPとして音声機能は必要なく、将来の通知・読み上げ等と合わせて実装すればよいため             |
| 音声読み上げに対応する          | **Future**  | MVP・日常利用の最低限の機能としては不要で、音声機能の拡張として実装するため               |
| アラーム・通知音を再生する        | **Future**  | MVP・日常利用の最低限の機能としては不要で、通知機能の拡張として実装するため               |

| 非機能要件                   | フェーズ       | 理由                                                       |
| ----------------------- | ---------- | -------------------------------------------------------- |
| Web UIを日常利用に支障なく動作させる   | **MVP**    | 凝ったUIは不要だが、画面表示やコンテンツ切替に著しい遅延・カクつきがなく、最低限快適に利用できる必要があるため |
| 離れた場所から情報を確認できる         | **MVP**    | 壁の高い位置への設置を想定しており、離れた場所からの視認性が基本的な利用条件となるため              |
| 文字を大きく見やすく表示する          | **MVP**    | 離れた場所からでも時計・予定・天気などの情報を確認できるようにするため                      |
| 長時間連続稼働できる              | **MVP**    | 日常的に稼働させるサイネージとして利用するため                                  |
| 電源投入後に自動起動する            | **MVP**    | 電源投入のたびに複雑な操作をせず、家電のように利用できるようにするため                      |
| アプリ異常終了時に自動復旧する         | **MVP**    | 長時間稼働中にアプリが異常終了しても、利用者の手動操作なしで表示を復旧できるようにするため            |
| Raspberry Pi再起動後に自動復旧する | **MVP**    | OSやRaspberry Piの再起動後に、利用者が手動でアプリを起動し直す必要をなくすため           |
| インターネット切断時も最低限の表示を継続する  | **MVP**    | ネットワーク障害によってサイネージ全体が利用できなくなることを防ぐため                      |
| 外部データをローカルにキャッシュする      | **MVP**    | インターネット切断時にも、取得済みの予定・天気などの情報を可能な範囲で表示するため                |
| 設定情報を再起動後も保持する          | **MVP**    | 再起動するたびに設定し直す必要をなくすため                                    |
| アプリケーションログを記録する         | **MVP**    | 開発中および運用中に不具合が発生した際、原因を調査できるようにするため                      |
| ソフトウェアを容易に更新できる         | **v1.0**   | MVPでは手動更新を許容し、日常運用する段階では修正や機能追加を容易に行えるようにするため            |
| 複数の画面サイズへ対応する           | **Future** | MVP・v1.0では使用するディスプレイを固定し、将来ディスプレイを変更する必要が生じた際に対応するため     |
| 縦置き・横置きへ対応する            | **Future** | MVP・v1.0では使用する設置方向を固定し、将来的に異なる設置方法が必要になった場合に対応を検討するため    |
