# Issue #9：天気の取得・表示の検証

## 範囲と状態

[Issue #9](https://github.com/rinYamano211/home-digital-signage/issues/9)で実装したOpen-Meteoの天気（CurrentWeather・HourlyWeather・WeeklyWeather）の取得・表示（PR #95・#96）を、Windows・CI・Raspberry Pi・実際のOpen-Meteoで確認した。設計は[technology-stack.md 16.6](../technology-stack.md#weather-issue-9-design)、[Backend開発手順「Weather Service」](../backend-development.md#weather-serviceissue-9実装済み実機確認済み一部繰越)、[Frontend開発手順 第12章](../frontend-development.md#12-天気の表示issue-9)に従う。RainForecast（Tomorrow.io）は[Issue #93](https://github.com/rinYamano211/home-digital-signage/issues/93)の範囲であり、本検証の対象外とする。

Raspberry Pi・実APIでの確認は、ユーザーが手動で行った。本番の配置（systemd・nginx・Release Directory）は#12の範囲であり、ここでは一時ディレクトリ（`~/signage-check`）にBuild成果物を置いて確認した。

- 確認日：2026-11-08
- 対象：main `49d17d5`（PR #96のMerge Commit。PR #95を含む）。PCでBuildした成果物をPiへ転送した。Pi上の成果物とCommitの照合は記録していない
- Raspberry Pi・画面：Issue #10の検証（[issue-10-schedule.md](issue-10-schedule.md)）と同じ環境（1280×800、Chromium Kioskモード）
- DB・`backend.env`：Issue #10の検証で作ったものを使い、`backend.env`に地点（緯度・経度）の2行を追記した。地点の値と`backend.env`の内容は記録しない
- 結果：24項目中22項目PASS。C1は一部未確認、E1は改善要（下記「繰越事項」）

## E：Raspberry Piの画面（合成データ）

検証画面のキー（Frontend開発手順 11.7・12.7）で、天気の合成データ（Wキー）とPollingの状態（Pキー）を切り替えた。

| No. | 確認項目                                                                                           | 結果   |
| --- | -------------------------------------------------------------------------------------------------- | ------ |
| E1  | 1280×800で、現在の気温・天気名・時間別・週間の文字が約3mから読める                                 | 改善要 |
| E2  | 出典の文字が、近くで読めて、遠くからは主表示の邪魔にならない                                       | PASS   |
| E3  | 「更新待ち」の札が内容と重ならない。「取得しています」「取得できません」で配置が崩れない           | PASS   |
| E4  | 日付またぎ：`明日 0時`とアクセント色の縦線。夜：月のアイコン。未知の天気コード：「？」と`天気不明` | PASS   |
| E5  | 枠の不足（5枠）・日数不足（3日）で、存在する分だけ左・上から並び、崩れない                         | PASS   |

- E1：画面内に収まり、重なりはなかった。一方、約3mからは気温・時間別予報の文字が小さく、天気アイコンもやや見づらかった。時間別予報の時系列も直感的に分かりにくかった。改善した後、実機で再確認する。
- E2：出典の文字は約3mからは読みにくいが、主表示の邪魔をしないことを優先し、不合格の理由としない。
- E3：「取得しています」は、天気の合成データを取得中にし、Pollingを`received`にした状態で確認した。
