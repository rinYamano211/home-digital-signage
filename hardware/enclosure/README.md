# 筐体CAD（CadQuery）

Issue #20の筐体CADのソース。寸法・要件の出典は[筐体要件・実測寸法・取付条件](../../docs/enclosure-requirements.md)（Issue #19）。

## 環境の作り方（Windows）

CadQueryは、Repoの外のvenv（このプロジェクト専用のPython環境）に入れる。Repoの中に作ると、Windowsのパスの長さの上限（260文字）を超えてインストールに失敗するため。

- 場所：`C:\Users\<ユーザー名>\.venvs\hds-enclosure`
- 確認した版：Python 3.13.7、CadQuery 2.8.0（`requirements.txt`で固定）

```powershell
python -m venv $env:USERPROFILE\.venvs\hds-enclosure
& $env:USERPROFILE\.venvs\hds-enclosure\Scripts\python -m pip install -r hardware/enclosure/requirements.txt
```

消すときは、venvのフォルダを削除する。

## 実行

Repoのルートで実行する。

```powershell
& $env:USERPROFILE\.venvs\hds-enclosure\Scripts\python hardware/enclosure/src/export.py
```

参照モデルの各部品の範囲（X・Y・奥行き）を表示し、`hardware/enclosure/out/`に図（SVG）を出力する。SVGはブラウザで開いて確認する。

```powershell
& $env:USERPROFILE\.venvs\hds-enclosure\Scripts\python hardware/enclosure/src/check.py
```

筐体の確認をする。1つでもNGがあれば、終了コード1で終わる。

- 干渉：筐体と参照モデルが重なる体積が0か
- 前面の縁：ガラスに被る幅が、表示領域にかからないか（Displayが隙間の分だけ動いても1.0以上の余裕）
- 造形範囲：外形がプリンタの造形範囲（320×320から余裕10を引いた310）に収まるか

## ファイル

| ファイル            | 内容                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `requirements.txt`  | CadQueryの版                                                                                                               |
| `src/params.py`     | 参照モデルと筐体に必要な寸法を集めたファイル。値ごとに「実測・計算・仮定・公式・設計」を書く。筐体の設計に合わせて値を足す |
| `src/reference.py`  | 参照モデル。筐体の中に入る物を、実測値から作った単純な箱で表す                                                             |
| `src/chassis.py`    | メインシャーシ（前面側の部品）と固定耳の押さえ板                                                                           |
| `src/rear_cover.py` | リアカバー（背面の部品）                                                                                                   |
| `src/check.py`      | 形状・干渉・押さえ板・リアカバーの載り・前面の縁・造形範囲の確認                                                           |
| `src/export.py`     | 参照モデル・メインシャーシ・リアカバー・組み立てた状態の図（SVG）の出力と、範囲の表示                                      |
| `out/*.svg`         | 出力した図。`export.py`で作り直せる                                                                                        |

## 座標

- `params.py`は、docsと同じ座標で書く：Displayを正面から見て左下の角が原点。X＝右、Y＝上、Z＝正面のガラス面から背面への奥行き。
- この座標は左手系のため、CADの中では`reference.to_cad`でZの符号を反転する（CADのZ＝−奥行き）。反転しないと、実物の鏡像になる。

## 参照モデル

実測値と仮定から作った、暫定の「筐体が入ってはいけない範囲」を、少し大きめの箱で表す。

- 実物の細かい形は再現していない。
- 参照モデルと重ならないことは、実機に組み付けられることを保証しない。組み付けられるかは試作で確かめる。
- 筐体の設計を進めるときに、必要に応じて形を細かくする。

| 名前            | 中身                                                                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `display`       | Display本体（薄い部分＋下側の基板がある部分。基板は左右いっぱいと仮定）                                                                               |
| `tabs`          | 下部の固定耳2つ（穴あき。穴の中心のYは仮定。下の円弧の中心と穴の中心は、Xが0.1ずれる）                                                                |
| `display_plugs` | 左側面の端子に挿したプラグ＋ケーブル（Zは基準面が未確認のため余裕を足す）                                                                             |
| `pi`            | Pi 5＋Active Cooler＋スペーサー（基板の外形は公式値、高さは仮定を含む計算値に余裕を足す）                                                             |
| `pi_plugs`      | Piの下側に挿したプラグ（X位置を測っていないため、基板の幅いっぱい・Piの高さいっぱいとする。安全側だが大きすぎるため、干渉が出すぎる場合は細かくする） |
| `rtc_space`     | RTC Battery（任意・後付け）を置くために空けておく範囲。Piの左の基板の上に25×25×高さ10（仮定。実物・公式資料の寸法は未確認）                           |

仮定と余裕の量は`params.py`に書いてある。強度・温度・組立適合性は検証していない。

## メインシャーシ

前面を下にして印刷する前提で作る（前面がきれいに出る。壁は床から立ち上がる）。

| 部分                   | 内容                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| 前面の板               | 厚み2.0。ガラスに被せる縁は、上2.5・下5.0・左2.5・右5.0（仮。見た目とのバランスで後から決める）               |
| 壁                     | 厚み2.4。Displayとの隙間0.5                                                                                   |
| 左サイドカバー         | 内側の幅54.1（プラグの出っ張り49.1＋余裕5）                                                                   |
| 下フレーム             | 固定耳を前から受ける台2つ（床の壁にもつなぐ）、押さえ板用のボス2つ、配線口2つ、吸気のスリット                 |
| 上の壁                 | 排気のスリット                                                                                                |
| 位置決め               | 左サイドカバーの側は壁がないため、Displayの左端にリブを2つ（厚み2.4。端子とプラグの範囲を避ける）             |
| リアカバー用のネジボス | 6つ。4つは床から立ち上がる。上の2つは壁から吊り、下に45度の支えを付けてサポートなしで印刷できる形にした       |
| ネジ                   | はんだごてがないため、樹脂に直接ねじ込むM3タッピングネジの前提で、下穴2.5（仮定）。リアカバー6本、押さえ板2本 |

外形は幅287.4×高さ162.8×奥行き49.4。奥行きは、Piの一番高い所（仮定を含む計算値39.4）に、余裕3とCoolerの上の隙間5（仮）を足して決めた。

### 固定耳の押さえ板（Displayの主固定）

PR #149のレビューで、固定耳の穴にネジを通す方式では位置のずれをほとんど吸収できないと分かった（耳の穴3.0にM3のネジでは隙間がなく、左右の穴の間隔約219は測定の誤差と印刷の縮みでずれるおそれがある）。ユーザーの判断で、押さえ板で挟む方式にした（2026-11-27）。

- 耳の穴にはネジを通さない。耳の後ろに押さえ板を当て、耳の内側の隣に立てたボスへM3タッピングネジで留める。板が耳を前へ押し、Displayのガラスを前面の縁に押し付ける。耳の前の台（隙間0.2）は、耳が前へたわみすぎないための受け。
- ボスの上面は耳の背面より0.3低くし、締めると板がたわんで耳を押す。
- 押さえ板は耳の外側の端から1.0内側からボスまで。耳の位置が左右に数mmずれても板が耳に掛かる（`check.py`で、耳に掛かる面積が約43mm²あることを確認）。
- ボスの下穴は深さ8（M3のねじ込みの目安6を満たす）。前面の板の表に2.7残る。
- ボスと耳を受ける台は、前面の板と床の壁の2面につなぐ。
- 押さえ板は別の部品（2枚）。平らに印刷できる。
- 主固定に既存の固定穴を使わないため、`docs/hardware.md` 10.4と`docs/enclosure-requirements.md` 4.2の記述の変更が必要（別のdocs PRで扱う）。
- 締める力、板のたわみ、実機での保持力は確かめていない。

### 配線口の通り方（図面上の確認）

長穴の幅の円が入るため、プラグの断面の対角線が穴の幅より短ければ、向きを合わせて通せる。

| 配線口            | 穴（幅×奥行き方向） | 通すプラグ（幅×厚み） | 断面の対角線 | 判定            |
| ----------------- | ------------------- | --------------------- | ------------ | --------------- |
| Pi用（中央下）    | 18×20               | Pi電源 12×7           | 13.9         | 通る（余裕4.1） |
| Pi用（例外）      | 18×20               | Micro HDMI 14.7×6.9   | 16.2         | 通る（余裕1.8） |
| Display用（左下） | 14×16               | Display電源 11×6.8    | 12.9         | 通る（余裕1.1） |
| Display用（例外） | 14×16               | Mini HDMI 10.9×6.9    | 12.9         | 通る（余裕1.1） |

- 組立の順：ケーブルを外から配線口に通してから、端子に挿す。
- Pi用の穴の位置（X＝133.6）は、Piの電源端子の位置の公式図面の値による参考値。端子の奥行きの位置も測っていないため、穴を奥行き方向に長くした。
- 実物のケーブルの硬さ・曲がり方、2本を同時に通したときの通りやすさは確かめていない。

### ケーブルを留める穴

下フレームの床の、各配線口の横に、結束バンド（幅2.5以下）を通す穴の組を開けた（穴2×4、間隔8）。端子と配線口の間でケーブルを床に留め、外から引っ張っても端子に力がかかりにくくする。

まだ作っていないもの：

- 配線口の縁の丸め（今は端を丸めた長穴だけ。#21で印刷条件と合わせて検討）

## リアカバー

背面を下にして印刷する前提で作る（内側の台や柱は床から積み上がる）。メインシャーシと同じ外形（287.4×162.8）、厚み2.4。組み立てたときの全体の奥行きは51.8。

| 部分                 | 内容                                                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ネジ穴               | 6つ（直径3.4）。シャーシのボスにM3タッピングネジで留める                                                                                                                                  |
| 補助の通気口         | Piの後ろに縦のスリット                                                                                                                                                                    |
| キーホール           | 2つ（X＝45と165。Displayの中央付近を挟んで左右対称）。直径9の丸い穴に壁のネジ・ピンの頭を通し、上へ10ずらして幅4.5の溝に掛ける。板の内側に、頭が入る深さ3.5の空間と、それを囲む台を付けた |
| ワイヤーを通す穴の組 | 2組（キーホールの下）。直径4の穴2つを、板の内側の溝でつなぐ。ワイヤー・ひもを外から入れて溝を通し、外へ出して結ぶ。ピクチャーレールのフックに掛ける                                       |
| 上側の押さえの柱     | 2本。Displayの上側（基板がない薄い部分）の背面との隙間0.3。リアカバーを付けると、Displayが後ろへ動くのを止める                                                                            |

荷重の流れ（壁掛け）：壁のネジ・ピン（またはワイヤー）→ キーホールの台（またはワイヤーの穴の組）→ 背面の板 → 6本のネジ → シャーシのボス → シャーシ → 前面の縁・押さえ板 → Display。

- キーホールとピクチャーレールは、どちらか一方を使う。両方を同時に使う前提ではない。
- キーホールの台・ワイヤーの穴の組・ネジの強度は、実機で確かめていない。
- Displayの上側の押さえは、リアカバーを付けたときだけ効く。リアカバーを外したときは、下の押さえ板2枚と前面の縁で支える。
- RTC Batteryの置き場所（`rtc_space`）は、メインシャーシ・押さえ板・リアカバーのどれとも重ならないことを`check.py`で確かめた。
